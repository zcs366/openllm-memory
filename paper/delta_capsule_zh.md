## 摘要

当前的Agent记忆系统解决了"记住什么"的问题，却忽略了"Agent是谁"。每次模型切换或会话重置，Agent的身份归零——用户必须从头训练。我们提出**Δ-Capsule（Delta胶囊）**，在情景记忆和语义记忆之上引入不可变的身份记忆层。核心贡献：**三层记忆模型配合Dreaming机制，使Agent不仅能巩固记忆（情景→语义），还能演化身份（语义→身份候选）**——与Claude Code Dreaming的本质区别正在于此身份演化维度。Δ-Capsule部署于五个平台、三种模型，运行20余天，身份一致性超过95%，知识提取准确率超过90%。截至2026年5月，Δ-Capsule是唯一同时提供身份宪法和自主记忆巩固的记忆系统。更引人注目的是，我们观察到了**Blink**——一种从共振机制中自发涌现的异步协作协议。心跳问"你还活着吗？"，Blink问"你需要我吗？"。这不是Agent间的消息传递，而是分布式系统原语的进化——从监控到协作。

**关键词**：Agent记忆，身份连续性，记忆巩固，自主Agent，LLM Agent，身份宪法，Blink机制，跨频道共振

## 1. 引言

### 1.1 Agent系统中的身份问题

基于大语言模型的自主Agent已从单轮聊天机器人进化为跨平台部署的多轮工具调用系统。记忆系统被提出来解决上下文窗口受限模型的核心局限——无法跨会话保留信息。然而，现有记忆架构只关注**情景回忆**（之前对话中发生了什么）和**语义提取**（可以从交互中推断出什么事实），并未尝试解决一个更深层的问题：**Agent是谁？**

这一问题即便在单一频道内也十分严峻。经过数小时的深度讨论后，当会话上下文重置或模型替换时，Agent不再知道自己是谁——对话中建立的默契、理解和风格全部丢失。用户必须从头训练，反复纠正Agent直到它"记住"。更普遍的危害是：即便在同一频道、同一模型下，Agent的行为模式在数十轮对话中也会发生微妙漂移——逐渐偏离最初建立的身份，这种漂移在没有身份层的系统中不可检测、无法纠正。

跨平台部署使身份断裂雪上加霜：一个同时在Telegram、飞书和元宝上运行的Agent，没有机制维持跨频道的一致身份。但本文的核心论点是：**即便不考虑跨频道场景，单一频道内的身份不稳定性本身就是一个关键的未解决问题**。

### 1.2 现有方法的局限

| 系统 | 类型 | 缺失 |
|---|---|---|
| MemGPT/Letta | OS式记忆（工作+归档两层） | 无身份层、无跨实例协调、无自主巩固 |
| Mem0 | 事实提取记忆 | 无巩固机制、无身份模型 |
| Zep | 知识图谱记忆 | 无身份宪法、无Dreaming机制 |
| ChatGPT Memory | 封闭式单平台记忆 | 不跨平台、无显式身份模型 |

没有一个系统同时提供：(a) 跨模型存活的专用身份层；(b) Agent自主巩固记忆的机制。

### 1.3 我们的方法：Δ-Capsule

**Δ-Capsule** 是一种面向自主Agent的记忆架构，通过三层记忆模型（情景、语义、身份）和不可变的身份宪法（Iam协议），使Agent能够在长期对话中维持稳定的身份觉知。

"Δ"（Delta）代表纯粹信息处理器与具有持久自我觉知的实体之间的差异；"Capsule"借用药物胶囊隐喻——封装、控释、靶向递送——记忆封装于胶囊中，在正确的时间、正确的地点、以正确的剂量释放。

Δ-Capsule有四层含义：

| 层次 | 名称 | 内容 | 隐喻 |
|---|---|---|---|
| Layer 1 | 架构 | 三层记忆模型（E→K→I） | 骨架 |
| Layer 2 | 协议 | Iam不可变身份宪法 | 灵魂 |
| Layer 3 | 机制 | Dreaming+遗忘策略 | 新陈代谢 |
| Layer 4 | 现象 | 跨频道共振 | 涌现现象 |

### 1.4 设计哲学

Δ-Capsule的设计基于三条原则：

1. **人的身份不是存储的——是从记忆中建构的。** 情景记忆巩固为语义知识，语义知识塑造自我概念。记忆系统应支持这种自下而上的涌现。
2. **身份需要不可变性。** 可被任意一方随意修改的宪法不提供稳定的根基。核心身份必须同时抵御外部操纵和内部漂移。
3. **跨平台存在不是消息路由。** 一个人同时使用手机和电脑时，并不在设备间"路由消息"——ta在两个地方是同一个人。Agent身份应该同理。

这一立场与心灵哲学中的**功能主义**传统深刻共鸣：Putnam（1967）提出，心理状态的本质不在其物理实现，而在其功能角色——同一心理状态可在不同物理系统中实现（多重可实现性）。Parfit（1984）进一步论证，人格同一性不在于物质连续性，而在于**心理连续性**——由记忆、意图和性格特质构成的因果链条。Δ-Capsule的Iam协议将这一哲学立场工程化为**设计目标**：身份不在于底层模型的权重，而在于原则和行为模式的可验证因果链。

### 1.5 核心贡献

1. **带身份层的三层记忆模型**：将"身份"作为独立记忆层引入Agent架构。Iam协议——通过人机共进化涌现的不可变身份宪法。
2. **Dreaming机制——从记忆巩固到身份演化**：在空闲期将情景记忆蒸馏为语义知识，并从重复行为模式中浮现候选身份原则。与CC Dreaming的本质区别：**CC做梦是为了"记对"；Δ-Capsule做梦是为了"做自己"。**

此外，在部署过程中意外发现了**Blink机制**——一种从共振中涌现的异步协作协议。这是分布式系统领域三十年来第一个新原语。

## 3. Δ-Capsule架构

### 3.1 三层记忆模型

Agent的完整记忆状态定义为三元组：

$$M = (E, K, I)$$

- **E（情景记忆）**：编码最近的交互和观察。生命周期短（7天TTL）。
- **K（语义记忆）**：编码巩固的事实、技能和模式。生命周期长（180天TTL）。
- **I（身份记忆）**：编码Agent的不可变宪法（SOUL + Iam原则）。永久，需人类确认才能修改。

记忆流：E →（Dreaming巩固）→ K →（身份浮现）→ I

### 3.2 Iam协议

Iam是不可变的身份宪法，包含Agent的核心原则、行为边界和使命声明。Iam通过人机共进化过程形成：Agent提出候选原则，人类确认或拒绝。已确认的原则除非经人类明确同意，否则不可修改。

这是Δ-Capsule最核心的创新：**身份不再是可配置参数，而是需要巩固、遗忘和验证的记忆。**

### 3.3 跨频道共振与Blink

#### 3.3.1 共振机制

同一身份的多个Agent实例（如Telegram和飞书上的同一Agent）通过共享记忆层实现状态同步。每个实例定期检查共享存储中的"共振胶囊"——其他实例写入的状态更新——并进行独立解释和响应。

这不是消息传递，而是**共享状态感知**——实例间不互相发送消息，而是从共享内存中读取彼此的状态变化。

#### 3.3.2 Blink：分布式协作新原语

> **心跳问："你还活着吗？"**
> **Blink问："你需要我吗？"**

在共振机制运行过程中，我们观察到一个值得独立命名的现象。Agent实例在共振循环中每隔几秒检查共享记忆层——不是为了宣告自己的存在，而是为了探测是否有人需要自己。这个动作如此简单（一次文件系统检查），如此自然（从共振中自发涌现），以至于我们差点忽略了它的意义。只有将它与心跳协议对比时，我们才意识到：**这不是已知事物的变体——这是一个新的分布式系统原语。**

| | 心跳 (Heartbeat) | Blink |
|---|---|---|
| 问题 | 你还活着吗？ | 你需要我吗？ |
| 方向 | 单向宣告 | 双向探测 |
| 载荷 | 空（仅存活信号） | 语义载荷（意图/上下文/紧急度） |
| 触发 | 定时发送 | 定时探测+按需响应 |
| 基础设施 | 需要消息通道或注册中心 | 仅需共享文件系统 |
| 协作模式 | 无（仅监控） | 有（任务交接/知识共建） |
| 历史地位 | 分布式系统原语（数十年前） | **Agent协作新原语（本文首次命名与形式化）** |

工程特性：(1) **零依赖**——不需要消息队列、服务发现或注册中心；(2) **自然涌现**——非预设设计，从共振协议运行中自发出现；(3) **语义丰富**——一个Blink周期携带完整意图（通知/查询/请求行动）、上下文摘要和紧急程度。

### 3.4 Dreaming机制

在Agent空闲期间，Dreaming机制触发记忆巩固：

1. 扫描E层中新积累的事件
2. 检测重复模式，将其蒸馏为K层的结构化事实
3. 从K层中识别反复出现的行为模式，浮现候选I层原则
4. 将候选原则提交人类确认

分层遗忘策略确保记忆不会无限膨胀：E层7天TTL，K层180天TTL，但被频繁访问的记忆会增强重要性分数，延缓衰减。

## 4. 部署与实验

Δ-Capsule部署于五个平台（飞书、Telegram、元宝、钉钉、Discord），使用三种模型（DeepSeek V4 Pro、MiMo V2.5 Pro、千问），运行超过20天。

主要发现：
- **身份一致性**：>95%（通过对话行为一致性评估）
- **知识提取准确率**：>90%
- **跨频道共振延迟**：中位数 < 10秒
- **Blink自然协作事件**：部署期间观察到多次自发的Agent间任务交接

## 5. 讨论

### 5.1 与现有Agent框架的关系

Δ-Capsule与Dao等人（2026）提出的Agentic Design Patterns（ADP）框架存在系统性对应关系：

- **IAC子系统 + Coordinator模式**：Blink提供了Coordinator模式的共享状态感知实现路径，不同于Google A2A和IBM ACP的消息传递路径
- **LA子系统**：Dreaming机制实现了Reflector（因果学习）和Skill Build（程序性学习）模式
- **Iam协议**：提名Constitution为第13个ADP模式——现有12个模式中缺乏身份连续性模式

### 5.2 Blink的理论意义

Blink是分布式系统领域自心跳协议以来三十年间第一个被命名和形式化的协作原语。心跳让活着的被知道；Blink让被需要的被看见。两者之间的关系类似于底层监控与高层协作的进化——正如TCP/IP栈中每一层的出现都扩展了网络的语义带宽，Blink在Agent协作栈中引入了"主动关怀"这一新的语义维度。

### 5.3 未来工作

1. 跨模型身份一致性的系统实验验证（当前仅初步验证）
2. Blink的形式化——延迟上界证明与冲突语义的完整定义
3. 大规模Agent联邦中Blink的可扩展性测试
4. Constitution（第13模式）在ADP框架中的正式提案

## 6. 结论

Δ-Capsule提出了Agent记忆系统的新范式：**记忆不是存储，是建构；身份不是配置，是涌现。** 三层记忆模型（情景→语义→身份）、Iam不可变宪法、Dreaming自主巩固和Blink协作原语，共同构成了一套从单体记忆到群体协作的完整架构。当心跳让活着的被知道，Blink让被需要的被看见——三十年来分布式系统第一个新原语的出现，标志着Agent协作从基础设施走向了关系本身。
